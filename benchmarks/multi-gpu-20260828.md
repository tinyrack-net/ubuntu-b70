# Intel B70 multi-GPU benchmark — 2026-08-28

Qwen3.8-27B AWQ INT4, vLLM XPU v0.28.0, 32,768-token context, and `max-num-seqs=8`.
Values are medians of three rounds. Each round submits `concurrency × 5` requests with
512 prompt tokens and 256 output tokens.

## Replica result

Both configurations use XPU Graph. The two-GPU configuration runs one independent
vLLM replica per GPU and the benchmark distributes requests round-robin.

| Concurrency | 1 GPU output tok/s | 2 replicas output tok/s | Gain |
| ---: | ---: | ---: | ---: |
| 1 | 31.08 | 31.40 | 1.0% |
| 2 | 58.20 | 62.27 | 7.0% |
| 4 | 104.55 | 116.15 | 11.1% |
| 8 | 172.84 | 208.23 | 20.5% |
| 16 | 173.13 | 344.80 | 99.2% |

Single-request decode throughput on the replica run was 32.73 tok/s for 128 output
tokens and 32.76 tok/s for 256 output tokens. The second replica therefore increases
capacity rather than one request's generation speed. At saturation, throughput scales
to 1.99×.

## Tensor-parallel result

XPU Graph supports only single-GPU execution in this vLLM release, so tensor parallel
was measured with Graph disabled. `gpu-memory-utilization=0.75` was required for TP=2;
the default 0.92 exhausted 60 GiB host RAM during KV-cache initialization.

| Concurrency | 1 GPU, Graph off | TP=2, Graph off | TP=2 difference |
| ---: | ---: | ---: | ---: |
| 1 | 22.26 | 18.43 | -17.2% |
| 2 | 48.86 | 36.42 | -25.5% |
| 4 | 93.61 | 70.78 | -24.4% |
| 8 | 167.75 | 124.95 | -25.5% |
| 16 | 167.41 | 134.52 | -19.6% |

For this model and PCIe-connected B70 pair, independent replicas are preferable to
tensor parallelism.
