# Intel B70 vLLM 성능 설정 조사 결과 (2026-08-29)

## 결론

단일 GPU 최고 성능 후보는 `intel/llm-scaler-vllm:0.21.0-b3.1`과
`RedHatAI/Qwen3.8-27B-INT4`, MTP speculative tokens 3의 조합이다. context 32768,
`max-num-seqs=4`, `max-num-batched-tokens=2048`, KV cache auto, prefix caching off,
XPU Graph 조건에서 C1 68.83 tok/s와 C4 190.14 tok/s를 기록했다. 현재 운영 기준보다
C1은 119.7%, C4는 80.4% 빠르고 C4 median TTFT도 1.1% 낮다.

후속 사용자 승인에 따라 Intel MTP3를 두 GPU의 vLLM 내부 DP2, 단일 8080 API로
승격했다. rank별 `max-num-seqs=2`로 전체 동시성 4를 유지하며 content canary와
체크섬 검증을 사용한다. 독립 2-replica 구성보다 운영 endpoint가 단순하고, 내부
queue 기반 load balancer가 각 rank에 요청을 분배한다.

## 안정성 및 기능 검증

- MTP on/off temperature 0, seed 0 프롬프트 4종의 응답 SHA-256이 모두 일치했다.
- MTP3 C4 5분 혼합 soak에서 한국어·코드·약 8K-token 장문 요청 187건이 모두 content
  marker 검증을 통과했다. bad content 0, API error 0, OOM 0, restart 0이었다.
- required tool call에서 지정한 함수와 arguments가 정상 반환됐다.
- DP2 C4 2분 혼합 stress 97건도 bad content/API error/OOM/restart 없이 통과했다.
- health, `/v1/models`, 체크포인트 SHA-256 검증이 모든 합격 후보에서 통과했다.
- upstream nightly `0.28.1rc1.dev43`은 기존 pointer overflow는 통과했지만 XPU warm-up의
  `causal_conv1d` speculative/non-spec 혼합 오류로 반복 종료되어 탈락했다.
- Intel 이미지 최초 pull은 루트 볼륨 부족으로 실패했다. 실패한 nightly 후보 컨테이너와
  정확한 nightly 이미지 하나를 제거한 뒤 재시도해 성공했으며 운영 이미지·모델 캐시는
  삭제하지 않았다.
- 실험 종료 후 사용하지 않는 Intel 실험 이미지 digest도 제거해 루트 사용률을 93%에서
  76%(29GB 여유)로 복구했다. 재현 profile과 모델 캐시는 보존했다.

## 운영 권고

1. 적용된 Intel image + RedHat INT4 + MTP3 + internal DP2 구성을 유지한다.
2. prefix caching은 끄고 `max-num-batched-tokens=2048`, rank별
   `max-num-seqs=2`를 유지한다.
3. content canary(5분, 2회 연속 실패 시 재시작)를 유지하고 24시간 장기 상태를
   관찰한다.
