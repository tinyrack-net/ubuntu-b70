## 결과 요약

- 고정 조건: 공식 `intel/llm-scaler-vllm:0.21.0-b3.1` image ID
  `sha256:032916bd9264da44cab3e99092ffaf12331072ec51c3b380cbbe5fd98eb0254b`,
  `RedHatAI/Qwen3.8-27B-INT4` revision
  `2fb0debc365fb6c1683d7d3ad7722470919627a8`, DP2, rank당 C4, MTP3,
  auto KV, batch tokens 2048, prefix caching off, eager off, Mamba cache/SSM dtype auto.
- 32K 교차 실행 `ON → OFF → ON → OFF`의 두 실행 median에서 Graph OFF는 C1
  output TPS -15.87%, tg128 decode -20.27%, C8 aggregate -1.86%, C8 TTFT
  +0.29%였다. 단일 요청 손실이 15%를 넘어 `운영 부적합`이다.
- 40K에서는 Graph ON marker가 30건 중 9건 실패했다. 실패 출력은 marker 불일치,
  비유한 logprob, 단일 토큰 붕괴였으며 OOM/restart/preemption은 없었다. Graph OFF는
  30/30 통과했다. 오염된 Graph ON 컨테이너에서 OFF로 전환하는 동안 DP rank 하나가
  초기화되지 않아 승인된 호스트 재부팅을 1회 수행했고, 재부팅 후에는 정상 기동했다.
- 40K 짧은 성능에서 OFF/ON은 C1 -12.90%, C8 -1.89%, C8 TTFT +6.21%로
  `절충 가능`이었다.

118,784는 96K 기동 시 측정한 KV tokens의 99%를 1,024-token 단위로 내린
후보였다. 118,528 prompt + 256 output 요청은 marker와 유한 logprob 조건을
만족했고, 장문 C2 2라운드 4/4 및 장문 2건+짧은 6건 혼합 C8 8/8도 정확했다.
MTP는 짧은 벤치마크에서 draft 44,898개 중 44,681개를 수락해 99.52% acceptance를
보였다. 다만 최대 결합 길이 요청 한 건에서 `<think>` 태그가 노출되어 엄격한 전체
품질 판정은 실패했다.

## 판정 및 복구

Graph OFF는 GDN 장문 출력 오염을 제거하고 auto KV에서 118,784 tokens까지 안정적으로
확장했지만, 핵심 단일 decode TPS가 18–20% 감소하므로 무성능회귀 목표를 만족하지
못한다. 운영 승격은 하지 않았다.

실험 종료 후 저장소 기본값인 32,768, Graph ON, auto KV, MTP3, DP2를
`make verify → make ping → make check → make apply`로 복구했다. 실제 컨테이너는
image digest 일치, `VLLM_XPU_ENABLE_XPU_GRAPH=1`, `--max-model-len 32768`, DP2,
restart 0, OOM false이며 canary timer는 active이고 마지막 실행은 success다.

복구 후 C8 soak에서는 두 차례 모두 장문 종류 한 건씩이 reasoning에 128-token 출력
예산을 전부 사용해 빈 content로 끝났다(첫 실행 50/51, 재실행 73/74). `!` 반복,
NaN, API 오류, restart/OOM은 아니고 required tool call은 두 번 모두 정상이었다.
이는 Graph OFF 잔류 상태가 아니라 현 Graph ON 운영 구성의 reasoning/output-budget
회귀로 별도 추적해야 한다.

## 후속 운영 결정

사용자 결정에 따라 장문 안정성을 단일 요청 TPS보다 우선해 2026-08-30에
118,784/Graph OFF를 운영 기본값으로 승격했다. 배포 후 118,528-token marker probe는
정확한 marker, 유한 logprob, 반복 및 `<think>` 노출 없음으로 통과했고 GPU당 KV는
122,496 tokens였다. 이어진 30초 C8 soak는 27건 정상, bad content/API error 0,
required tool call 정상, restart/OOM 0으로 통과했다. content canary timer는 active이며
수동 canary 실행도 exit 0이었다.

배포 후 기본 `make benchmark-api`를 다시 실행한 결과 tg128/tg256 decode는
66.24/63.56 tok/s, C1/C2/C4/C8 aggregate는 각각
59.15/111.20/203.72/361.83 tok/s였다. C8 median TTFT는 958.08ms였고 benchmark
전후 restart/OOM은 0이었다. 결과 원본은
`benchmarks/results/20260830T094217Z-vllm-openai.json`이다.
